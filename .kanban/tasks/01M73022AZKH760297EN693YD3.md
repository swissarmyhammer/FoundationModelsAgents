## What
Add the write core of AG-9 (D87, D175). It has no tool code. The tool operations of the next task use it.

Make the new file `Sources/FoundationModelsAgents/Registry/AgentWriter.swift`:
- `public enum AgentWriteLayer: String, Sendable, CaseIterable { case user, project }`. The default is `.user`. The names and the values are the same as the `layer` option of the `skills` tool (SK-6, D175).
- `struct AgentWriter` over `AgentRegistry.localLayers`. The target layer is the highest local layer whose `DotfolderStack.Layer.source` is `.user` or `.project`. A `.defaults` layer and each marketplace layer are read-only. When the stack has no layer of that source, the writer gives the error `layerUnavailable(AgentWriteLayer)`.
- The project layer is the `.project` layer of the registry, not a folder that the writer computes. In ACPAgent, `AgentsComposition.makeAgentRegistry(context:marketplaces:)` makes one registry for each session from `context.settingsFolders.stack(for: .agents, workingDirectory: context.workingDirectory)`. Thus the project layer is `<cwd of the session>/.agents/`, and the user layer is the root settings folder (in the app the iCloud `Agents/` folder). A child run that works in a different folder writes to the project layer of the registry of its runner.

The existence rule. It is the same rule as the catalog scan (`AgentFolderFormScan` in `Sources/FoundationModelsAgents/Registry/AgentLayerScan.swift`):
- An agent `<id>` exists in a layer when `<root>/<id>/AGENT.md` or `<root>/agents/<id>/AGENT.md` exists (or the placeholder file of that `AGENT.md`). A folder with no `AGENT.md` is not an agent.
- The agent `default` (`AgentCatalog.defaultAgentID`) exists in a layer when the root `AGENT.md` of the layer exists. Its folder is the layer root.

Reserved ids. Refuse with `reservedID(id)` each id that is a folder name of the layer layout, because a write or a delete of that folder damages other items: `agents` (the dotfolder form), `skills`, `rules`, `partials`. Names that start with `_` (`_skills`, `_rules`, `_partials`) are already invalid ids.

Operations:
- `add(id:content:layer:)`: refuse an id that `AgentDefinitionRules.isValidID` refuses (`invalidID`), and a reserved id. Refuse when the agent exists in the target layer (`alreadyExists`). An agent of the same id in a lower layer is not an error: the new agent overrides it. For `default`, write the root `AGENT.md`. For each other id, make `<root>/<id>/` and write `<root>/<id>/AGENT.md`.
- `edit(id:document:content:layer:)`: `document` is a relative path in the agent folder. The default is `AGENT.md`. Refuse an empty or absolute path and a path with a `..` component, and refuse a path that `PathConfinement.isConfined(_ candidate: URL, to root: URL) -> Bool` (module `FoundationModelsExtras`, `Sources/FoundationModelsExtras/PathConfinement.swift`) refuses for the agent folder (`unsafeDocument`). For `default`, also refuse a path whose first component is the name of a child folder of the layer root that holds a different item (each folder of an agent, `agents`, `_skills`, `_rules`, `_partials`). Refuse when the agent does not exist in the target layer (`notFound(id, layer)`). The error text names each layer where the agent exists, so the model can select the correct layer or use `add agent` for an override. When both forms exist in the layer, edit the form that the catalog reads (the same precedence as `AgentFolderFormScan`). Make the folders of a new document. Replace the full text of the document.
- `remove(id:layer:)`: refuse `default` (`cannotRemoveDefault`), because its folder is the layer root. Refuse a reserved id. Refuse when the agent does not exist in the target layer (`notFound`). Delete each form of the agent in the target layer: `<root>/<id>/` and `<root>/agents/<id>/`. Thus no copy of that layer stays in the catalog.
- Each write and each delete uses `NSFileCoordinator` (`coordinate(writingItemAt:options:)` with `.forReplacing` for a write and `.forDeleting` for a delete), in the same form as `AgentCatalogBuilder.coordinatedRead`. A coordination error gives `coordinationFailed(reason)`.
- `AgentWriterError: Error, Equatable` with a corrective `message` for each case, in Simplified Technical English.
- Each operation returns the URL of each file or folder that it changed.
- The writer does not reload. The caller calls `AgentRegistry.reload()`.

## Acceptance Criteria
- [ ] `add` writes `<user root>/<id>/AGENT.md` for `layer: .user` and `<project root>/<id>/AGENT.md` for `layer: .project`, where each root is the root of that layer of the registry.
- [ ] `add`, `edit` and `remove` with the id `agents`, `skills`, `rules` or `partials` give `reservedID` and change no file.
- [ ] `edit` of `default` with `layer: .user` replaces the root `AGENT.md` of the user layer. `edit` of `default` in a layer with no root `AGENT.md` gives `notFound`.
- [ ] `edit` of a folder that has no `AGENT.md` gives `notFound`.
- [ ] `edit` with `document: "notes/a.md"` writes a document in the agent folder. `../x.md`, `/tmp/x.md` and a symbolic link out of the folder are refused, and no file changes.
- [ ] `remove` deletes both forms of the agent in the target layer. A copy in a different layer stays.
- [ ] A write never goes to a `.defaults` layer or a marketplace layer.
- [ ] Each error case gives its `AgentWriterError` and changes no file.
