## What
`AgentsTool` conforms to `GraphQLEndpointTool` (EXTRAS-7, D75; EXTRAS-9 rev 2 rule 1). Its `graphQLEndpoints` is a list of one: the `AgentsGraph` of AG-8a over the same `AgentRegistry` as `context.runner.registry`, so the model and a client see one catalog. The tool stays an `OperationTool<AgentsToolContext>` op tool: its name, description, schema and operations do not change, and the model sends no GraphQL text to it. A host finds the endpoint with `tool as? any GraphQLEndpointTool`.

Rule 1 (rev 2): the endpoint is made once per port, that is, once per `AgentRegistry`, not per `AgentsTool` copy. Each tool of each session and run over one registry gives the same `AgentsGraph` instance, so (with AG-8c) every copy gives the same cursor. Keep the endpoint on the registry (or a per-registry holder) and have the tool return it; do not make one in `make(context:)` or on each read of `graphQLEndpoints`.

Decide and document what a `messagingOnly` tool gives: the endpoint reads the catalog, not the grant of the model, so give the endpoint for both grants (the host lists the endpoint of the session folder, not of one run).

Update the README/DocC and the doc comment of `AgentsTool` to name the endpoint.
