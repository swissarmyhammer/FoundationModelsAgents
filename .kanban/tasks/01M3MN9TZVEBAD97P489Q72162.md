## Why
Design of 2026-09-28 (item B and items 2 and 4): logs use `Logging.Logger` (swift-log), never `os.Logger`. A log message and its metadata never carry content.

## What
- One `Logging.Logger` with the label from `AgentsTelemetry` (task ^96s67ks), held by the runner or the run (`Run/AgentRunner.swift`, `Run/AgentRun.swift`). A host can pass its own `Logger`; the default is `Logger(label:)` from the vocabulary. Do not bootstrap `LoggingSystem` in the library.
- Records, each with the metadata keys from `AgentsTelemetry` (agent name, run id, parent run id, caller session id, depth, outcome) and no content:
  - run started (`.info`);
  - run finished (`.info`), with the duration;
  - run failed (`.error`), with the failure kind (hitMaxTurns, error, stopped, catalogNotLoaded, setup failure) and the error type name only; no error message text if it can hold model or tool content;
  - run cancelled (`.info`).
- The "enter" record of task ^wprxwv2 is separate; do not write it two times.
- Confirm that `Sources` has no `os.Logger`, `import os`, or `OSSignposter` (it has none now); add a guard test so none comes back.
