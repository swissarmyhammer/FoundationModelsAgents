## What
Plan.md §8 step 7, §9.3 (children, depth). M5, second part.

- In `Sources/FoundationModelsAgents/Run/AgentRun.swift`, pass an `agentsTool` closure to `ToolResolver` that makes a new `AgentsTool` with `try await AgentsTool.make(context:)` for this run, limited by `Agent(a, b)`. The child is started with this run's session as the caller.
- Create `Sources/FoundationModelsAgents/Run/AgentRun+Children.swift`:
  - The run records the runs that it started.
  - After its task turn, while a child is open or a post is unread, the run waits. Each time a child finishes, the run calls `session.dispatchNextPrompt()`; the Router runs one turn with the staged posts. The model can start more children.
  - A run that waits for children holds no concurrency slot. A delivery turn never checks the limit.
  - When no child is open and no post is unread, the text of the last turn is the result.
  - A cancel, or a failure with open children, cancels the children, waits for their tasks, then closes the session and posts.
- Depth: a host-started run has depth 1; a child has its parent's depth plus 1. Above `maxDepth` `start agent` gives a corrective.
- Model `inherit` in a child uses the slot of the calling run. A run started from a session that is not a run (the host's root session) uses `environment.defaultSlot`. Write this rule in the doc comment of the slot lookup.
- `check agent` running text adds "It waits for `N` agents that it started." after its turn.
