title: An agent run ends on the Router's no-work, so a background result that settles inside an answer is answered
---
From the Router session (bench run planner24, django__django-13447, coder session …27NG7G). A runCode background run finished during the task-prompt answer, and its result mail waited in the queue as run mail. When that answer ended, AgentRun's idle rule (acceptedMessagesIfIdle / waitsForNoUserInput) skipped run mail, judged the session idle, kept the status text "waiting on …" as the report, and closed the session. The close cancelled the answer that carried the result.

Fix: the run tracks the work events of its session (workStarted/workEnded). Idle requires no work, and workEnded triggers a new idle check. Test: BackgroundResultEndTests, with a gated background tool that settles inside the task-prompt answer. #bug
