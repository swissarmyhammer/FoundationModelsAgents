## What

`check agent` on a running child gives no sign that its result comes by itself, so the model polls it in a loop. In bench24-1023b, django__django-14999, the root polled `check agent` again and again and got the same answer each time:

```
Agent diagnose (01M5PD2HHJEYZZCTNHR3XE4NR6) is running.
Phase: the task turn.
Passes: 0.
Last tools: none.
Text so far: none.
```

The user's ask (2026-10-24): "we should have a better message than that and explain that there is no need to loop and check, you can just stop and wait for mail".

The right words exist already. Extras `PendingRunEnvelope.pendingWorkInstruction` (FoundationModelsExtras `Sources/FoundationModelsExtras/Hosting/PendingRunEnvelope.swift:43-49`) says that the result comes as a new message, that the model need not wait, check or ask, and that it can do nothing until then. `start agent` uses it already (`AgentsToolText.swift:169`). Extras owns the one copy, and Multitool uses it too. Do not write a second copy.

- [ ] `Sources/FoundationModelsAgents/Run/AgentRun+FinalMessage.swift:42-46` (`runningText`): for a run in operation, give the heading "Agent <name> (<id>) is still working.", then `PendingRunEnvelope.pendingWorkInstruction`, then one progress line: "Progress: <passes> passes; last tools: <tools>; text so far: <tail>." Keep the paused sentence and the waiting sentence when they apply.
- [ ] **A repeated check with no progress.** When the same caller checks the same run again and nothing changed (the same passes, tools and text), lead with: "You checked this agent before, and nothing changed." Keep the last reported progress per run and per caller, in the run's storage.
- [ ] `start agent`: no change, because it uses the shared text already.

- [ ] The texts of a settled, cancelled or failed run are unchanged.
