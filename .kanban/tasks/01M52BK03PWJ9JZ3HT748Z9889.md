## Facts

Two full runs hung on Router e2688ac2:
- `base.log`: the task 45 sources were stashed;
- `full2.log`: with the task 45 sources.

Each of these tests has a "started" line and no end line in both logs:
- AgentSchedulingTests `checkWithNoIDListsOnlyRunsOfCaller`
- CheckAgentProgressTests `answerToMailGivesProgress` (`base.log` only; it passed in `full2.log` after 1.904 s)
- NestedRunTests+Idle `answerToMailThatStartsChildWaitsForIt`
- AgentsDemoProfileModeTests `chatModeWritesTheAnswerToTheMail` and `chatModeCancelsOpenRunsBeforeClose`
- TelemetryContentSafetyTests `messagesCarryNoContent`

The paused-mail tests also hung in these runs. Their cause is known (cause 1): an answer to mail alone counts toward `mailOnlyAnswerLimit` only when it starts a new background run. Commit b763e82 corrects these tests with `pausedLimit = 0`.

The hung runs have these facts:
- Each log has all 1001 test starts. Thus no test waited for a parallel slot.
- The `sample` output of the hung test process shows no blocked thread. The main thread is in `swift_task_asyncMainDrainQueue`, and each other thread is an idle worker. There is no ulock, mutex, condition or semaphore wait. Thus an async continuation does not resume.
- The disk was full or almost full at about the time of the hung runs.

After that time, three runs did not hang. All three used Router e2688ac2, Extras 016c5a8 and limit 100 for the 6 tests:
- one log run of `checkWithNoIDListsOnlyRunsOfCaller` (0.116 s);
- two full runs (530/530).

## Refuted causes

- Extras 11b7c7e..016c5a8: the only change makes `holdingRunToken` public. It does not change behavior.
- The limit: line 147 of NestedRunTests+Messages.swift is the default, 100, and it did not change.
- Tests that wait behind other tests: the tests have no `.serialized` and no global actor. Each test makes a new Router (ScriptedProfile.swift:53) and its own `GenerationQueue` (ScriptedSessionBackend.swift:137).
- A disk write error: each write path catches the error, logs it and drops the data, or fails in setup:
  - the Router journal chain does not throw (OperationEventSink.swift:8; JSONLAppend.swift:109-118);
  - the sidecar catches the error (SessionSidecar.swift:360-368);
  - a RecordingRootLock ENOSPC drops the event (Sinks.swift:148-156);
  - Agents and the Extras run plane write no files.
